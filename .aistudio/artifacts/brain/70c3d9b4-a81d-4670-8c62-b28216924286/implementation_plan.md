# تطبيق أندرويد لنظام إدارة طلبات المطبخ الاحترافي (KOMS Mobile)

خطة متكاملة ومدروسة لبناء تطبيق أندرويد للهواتف الذكية بنظام Jetpack Compose و Material Design 3 يجسد النظام الاحترافي لإدارة طلبات وتوريدات المطبخ ومطاعم الخدمة المتميزة، وموجه لجميع موظفي المطبخ (الشيف العمومي، المساعدين الخمسة، مستلمي التوريدات) للعمل بسرعة وكفاءة مجاناً ودون تعقيد.

---

## مراجعة اختيارات المستخدم والقرارات الحاسمة (User Review & Confirmed Decisions)

> [!IMPORTANT]
> بناءً على إجابات الأسئلة التوضيحية في المرحلة السابقة، تم اعتماد المعايير التالية كأساس للتنفيذ:

- **طريقة تسجيل الدخول والتبديل (Confirmed)**: اعتماد شاشة دخول سريعة وبديهية تتيح اختيار الموظف أو الشيف بنقرة واحدة مع رمز PIN مكون من 4 أرقام، مما يتيح التبديل الفوري بين الموظفين أثناء ضغط العمل داخل المطبخ دون الحاجة لكتابة بريد إلكتروني معقد.
- **التركيز الأساسي للمرحلة الأولى (Confirmed)**:
  1. شاشة الطلبيات المتخصصة وقوائم التصنيفات (خضروات، لحوم، دواجن، توابل، صصوصات، بقالة، ألبان، مخبوزات، أدوات تعبئة ونظافة) مع ميزة الإرسال الفوري المنظم عبر WhatsApp للموردين وللشيف العمومي (Chef CC).
  2. شاشة فحص الاستلام وضبط الجودة (HACCP Receiving) مع قياس وتسجيل درجات الحرارة والكميات المستلمة والمرفوضة وحالة التغليف.
  3. بطاقات المتابعة وسجل الطلبيات وتتبع الحالات اليومية.
- **استراتيجية التخزين والأداء (Confirmed)**: قاعدة بيانات محلية فائقة السرعة على الهاتف بنظام **Android Room (SQLite)** مع كاش تلقائي ومعالجة كاملة دون الحاجة لشبكة إنترنت (Offline-First)، مع بنية جاهزة للمزامنة السحابية.

## 1. نظرة عامة ومفهوم التطبيق (Overview & Core Concept)

### ما الذي يقدمه التطبيق
تطبيق أندرويد محلي للهواتف مصمم خصيصاً لبيئة المطابخ التجارية، يحل مشكلة التخبط وضياع الوقت في تسجيل طلبيات المطبخ واستلام البضائع من الموردين:
- يضم الكتالوج القياسي لجميع المكونات (أكثر من 180 صنف موزعة على 10+ تصنيفات متخصصة) مع معدلات الاستهلاك المرجعية (Par Levels).
- يتيح لمساعدي الشيف ملء الكميات المطلوبة بنقرة زر وضغط زر الإرسال عبر WhatsApp بنص منظم وموحد للمورد مع إرسال نسخة للشيف التنفيذي فوراً.
- يتيح لمسؤولي الاستلام إجراء الفحص الفوري عند وصول شاحنة التوريد (فحص درجة الحرارة HACCP، حالة التغليف، والكميات المقبولة/المرفوضة).

### الفئة المستهدفة والمستخدمون
1. **الشيف العمومي (Executive / Head Chef)**: الإشراف الشامل، وتعديل ومتابعة الجداول ومراجعة التقارير.
2. **مساعدو المطبخ (Kitchen Assistants 1 to 5)**: ملء طلبيات الأقسام المحددة لكل مساعد (خضروات، لحوم، دواجن، نواشف، أدوات).
3. **مسؤولو الاستلام وفاحصو الجودة (Receivers & QA)**: فحص شحنات التوريد اليومية ومطابقتها قبل توقيع الفاتورة.

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

### الاتجاه الجمالي والألوان
- **سمة المطبخ الاحترافي الأنيق (Culinary Dark Theme)**: خلفيات داكنة عميقة بلون الأردواز والحجر الطبيعي (`Stone 950` / `#0C0A09` و `Stone 900` / `#1C1917`) مستوحاة من مطابخ الفنادق والمطاعم الراقية، مما يقلل إجهاد العين ويوفر استهلاك البطارية.
- **ألوان التمييز والتنبيه**:
  - العنبر الدافئ الذهبي (`Amber 500` / `#F59E0B`) للعناصر النشطة وأزرار الإجراءات الرئيسية.
  - الأخضر الزمردي الزاهي (`Emerald 500` / `#10B981`) للواتساب وحالات الاكتمال والجودة العالية.
  - الأحمر المرجاني الحذر (`Rose 500` / `#F43F5E`) لتنبيهات درجات الحرارة الزائدة والمرفوضات.
- **الطباعة والخطوط (Typography)**: اعتماد خط عربي حديث بتنسيق واضح مريح للقراءة مع تباين عالي للأرقام والكميات.
- **أهداف اللمس المريحة**: جميع الأزرار وعناصر الزيادة والنقصان لا تقل عن 48dp x 48dp لتسهيل الضغط حتى بأصابع مبللة أو أثناء ارتداء قفازات المطبخ.

### رحلة المستخدم والشاشات الرئيسية (Core Screens Flow)

```
┌───────────────────────────────────────────────────────────┐
│                      شاشة قفل ودخول الموظفين               │
│         اختيار سريع لبطاقة الموظف + إدخال رمز PIN الـ 4 أرقام    │
└─────────────────────────────┬─────────────────────────────┘
                              │
                              ▼
┌───────────────────────────────────────────────────────────┐
│                  الشاشة الرئيسية (شريط التنقل السفلي)       │
│  [ الطلبيات ]   [ فحص الاستلام ]   [ سجل الطلبات ]   [ الإعدادات/الشيف ] │
└──────┬──────────────────────┬──────────────────────┬──────┘
       │                      │                      │
       ▼                      ▼                      ▼
┌──────────────┐       ┌──────────────┐       ┌──────────────┐
│ شاشة الطلبيات │       │ فحص الاستلام  │       │ سجل العمليات │
│  والأقسام 10  │       │  HACCP QA    │       │ والتتبع اليومي│
│  + واتساب    │       │ قياس الحرارة │       │ والتصفية     │
└──────────────┘       └──────────────┘       └──────────────┘
```

1. **شاشة الدخول واختيار الموظف (Staff PIN Screen)**:
   - بطاقات تعريفية للموظفين (الشيف، المساعد 1، المساعد 2، ...، مسؤول الاستلام).
   - لوحة أرقام رقمية سلسة لتأكيد الدخول الفوري دون إنترنت.
2. **شاشة تحضير الطلبيات (Orders & Columnar Dispatch View)**:
   - تصنيفات علوية (خضار، لحوم، دواجن، بهارات، صوصات، بقالة، ألبان، تغليف...).
   - جدول للأصناف يتضمن: اسم الصنف، الوحدة (كجم، كرتونة، ربطة، علبة)، معدل الطلب اليومي، وحقل إدخال الكمية مع أزرار (+ / -) سريعة.
   - زر بارز باللون الأخضر: "إرسال عبر WhatsApp" يفتح محادثة المورد مباشرة بنص الطلب الرسمي، مع خيار مشاركة نسخة ثانية للشيف العمومي (Chef CC).
3. **شاشة الاستلام وضبط الجودة (Receiving & QA Inspection)**:
   - قائمة الشحنات المتوقع وصولها اليوم مع موعد الوصول المستهدف (01:00 ظهراً).
   - نموذج فحص معايير الهاسب HACCP: قياس درجة الحرارة (°C)، سلامة التغليف، جودة المنتج، تحديد الكمية المستلمة والكمية المرفوضة مع سبب الرفض.
4. **سجل وتاريخ الطلبيات (Orders History & Workflow Tracker)**:
   - بطاقات ملونة حسب حالة الطلب (مخطط، تم الإرسال، في انتظار التوصيل، جاري الاستلام، مكتمل، معلق).
   - تفاصيل وسجل زمني (Audit Trail) للتحولات والملاحظات.

## 3. القرارات التقنية والهندسية (Key Architectural Decisions)

- **استخدام Jetpack Compose بالكامل**: بنية برمجية حديثة 100% بلغة Kotlin، متجاوبة مع كافة مقاسات شاشات الهواتف وأجهزة التابلت المستخدمة في المطابخ.
- **قاعدة بيانات Room المحلية المعزولة مسبقاً**:
  - `OrderEntity` و `OrderItemEntity`: تخزين الطلبيات وعناصرها مع تاريخ الطلب والتوقيت والحالة.
  - `ProductEntity`: الأصناف الـ 180+ مع الكود والاسم ومعدل الاستهلاك والوحدة والتصنيف.
  - `CategoryEntity`: تصنيفات المطبخ مع جدول المواعيد والموظف المسؤول.
  - `ReceivingLogEntity`: سجلات فحص الاستلام ودرجات الحرارة والمرفوضات.
  - `UserEntity`: بيانات الموظفين وأرقامهم الوظيفية ورموز PIN الخاصة بهم.
- **بذر البيانات التلقائي (Pre-populating Seed Data)**:
  - عند تشغيل التطبيق لأول مرة، يتم ملء قاعدة بيانات Room ببيانات KOMS الأصلية (الموظفين الخمسة، التصنيفات، وأكثر من 180 صنف حقيقي بأسماء عربية دقيقة وأوزانها ووحداتها).
- **التكامل الحقيقي مع WhatsApp Click-to-Chat**:
  - استخدام `Intent(Intent.ACTION_VIEW)` مع رابط `https://wa.me/20xxxxxxxxxx?text=...` مهيأ بترميز URL UTF-8 السليم، مما يفتح تطبيق واتساب المثبت على الهاتف فوراً مع تنسيق ماركداون احترافي بالخط العريض والنقاط.

## 5. توصيات المرحلة الأولى وخريطة الطريق (Phase 1 Recommendations)

1. **إتاحة التطبيق مجاناً وبلا قيود لكافة موظفي المطبخ**: جعل التطبيق مستقلاً ذاتياً على أجهزة الأندرويد، بحيث يستطيع كل شيف ومساعد تثبيت التطبيق والبدء في إدارة الطلبيات فوراً.
2. **الحفاظ على قاعدة الأرقام المصرية والدولية في واتساب**: تعقيم أرقام الهواتف تلقائياً لتبدأ برمز الدولة (`+20` لمصر أو أي رقم دولي) لتفادي أي خطأ أثناء إطلاق المحادثة.
3. **تنبيه وقت الوصول الإلزامي**: تثبيت تنبيه وصفي بأن وصول طلبيات الخضار والطازج محدد بالساعة 01:00 ظهراً، مع إبراز أي تأخير يتجاوز 24 ساعة.
4. **دعم الترقية اللاحقة للربط السحابي**: تهيئة بنية قاعدة البيانات المحلية بحيث تقبل مستقبلاً الربط بمزامنة Firestore دون الحاجة لتغيير هيكل الجداول.
